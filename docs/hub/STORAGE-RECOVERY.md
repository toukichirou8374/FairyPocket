# H2 資料儲存與復原

## 位置與格式
- 資料夾：`private/allay-hub/`（在 private/ 底下，不會上傳）。
  - `hub.json`：綁定碼（只存雜湊）、待確認的綁定、鎖定狀態、身分索引。
  - `pets/<petId>.json`：每隻悅靈一份，狀態、epoch、控制者、去重紀錄、記憶、對話、冒險紀錄、意圖都在同一份。
- 每份檔案的外層：`{ format: "fairy-hub-doc", hubSchema: 1, sha256, body }`。`sha256` 是 body 以固定順序序列化後的雜湊。

## 交易（一次寫入）
1. 計算新的文件（在記憶體的複本上，失敗就整個丟掉）。
2. 寫入 `<name>.tmp.json` 並 fsync。
3. 把目前的正式檔複製成 `<name>.prev.json`。
4. 把暫存檔改名成正式檔（NTFS 上是原子的）。
5. **成功後**才更新記憶體快取、回傳 ACK。

任何一步失敗都回 `503 STORE_UNAVAILABLE`：記憶體快取不變、正式檔不變，不會有部分寫入。
因為一個請求從讀取到寫入之間沒有 `await`，同一份文件的寫入不會交錯（Node 單執行緒）。

## 啟動時的復原
| 情況 | 處理 | 測試 |
|---|---|---|
| 正式檔正常 | 直接使用 | 「寫入後重啟仍在」 |
| 留下暫存檔（當機在步驟 2–3） | 使用正式檔（那次寫入沒有 ACK，不算），刪掉暫存檔 | 「當機在暫存檔寫好、還沒換上」 |
| 正式檔損壞（檢查碼不符） | 用前一版復原，並重新寫好正式檔 | 「正式檔損壞：用前一版復原」 |
| 正式檔不見、暫存檔完整 | 用暫存檔復原 | 「正式檔不見但暫存檔完整」 |
| 全部損壞 | **拒絕載入**、回報 `failed`，那隻悅靈的請求回 503；壞掉的檔案保留給人檢查 | 「全部損壞：拒絕載入」 |

轉接服務啟動時會印出：載入幾隻、復原幾隻、無法載入幾隻。

## 去重的耐久性
- 去重紀錄（角色＋來源 ID＋opId → 內容雜湊、當時的 rev 與結果）和狀態在**同一份檔案、同一次交易**寫入。
- 已 ACK 的事件在重啟後重送：回 `DUPLICATE` 與當初的結果（測試「重啟：…重送只回 DUPLICATE」）。
- 沒 ACK 的事件（例如儲存失敗）重送：會正常套用一次（測試「儲存不可用：…恢復後重送才套用」）。
- 保留 30 天；每隻上限 20,000 筆，滿了回 `507 CAPACITY_REJECTED`，不會刪掉未過期的紀錄。
- 超過 30 天被清掉的紀錄如果被重送：因為 `baseRevision` 早已過時，會被 `REVISION_CONFLICT` 擋下，不會重算。

## 備份與還原
```
node scripts/hub/backup-cli.mjs backup <放快照的資料夾>
node scripts/hub/backup-cli.mjs verify <快照>
node scripts/hub/backup-cli.mjs restore <快照>        ← 先停止轉接服務
```
- 備份只複製正式檔，並先確認每份的檢查碼正確；同時寫入 `manifest.json`（每個檔案的 SHA-256）。
- 還原先完整驗證（清單、每個檔案的雜湊、每份文件的檢查碼），任何一項不對就**完全不動**原資料。
- 驗證通過後寫到暫存資料夾，再把原資料夾改名為 `allay-hub.old-<時間>`、暫存資料夾改名成正式資料夾。
- 測試：「備份 → 驗證 → 還原；竄改過的快照拒絕還原；原資料保留」、「備份工具（CLI）」。

## 尚未涵蓋
- 多個程序同時寫入（目前只有一個轉接服務）。
- 磁碟本身壞軌或整顆硬碟故障（需要放到別顆硬碟的定期備份；排程備份另批處理）。
- 還原時如果轉接服務還在執行，記憶體裡的資料會蓋回去：**還原前必須先停止轉接服務**。
